Test d’échangeabilité : l’ordre canonique est-il trop vraisemblable ?

Si le modèle n’a jamais vu le benchmark, l’ordre dans lequel le jeu de test est publié n’a rien de spécial : sa log-vraisemblance est tirée de la même loi que celle de n’importe quel ordre permuté. Le test compare donc l’ordre canonique à K = 1000 ordres mélangés. C’est la version de base du test ; Oren et al. retiennent une variante par fragments (shards) plus puissante.

Absence de signal ≠ absence de contamination.
Le test répond oui ou non, avec une p-valeur. Il ne dit pas de combien le score est gonflé : une p-valeur minuscule n’indique pas une grosse inflation, et une p-valeur élevée n’en exclut aucune. Pour mesurer l’inflation, il faut mesurer des performances : sur une version rafraîchie ou perturbée du benchmark, ou en comparant les exemples marqués contaminés aux autres.

Modèle jouet, données illustratives : ce ne sont pas les résultats d’Oren et al. Hypothèses du jouet : la log-vraisemblance d’un ordre est la somme d’affinités aléatoires fixes entre exemples voisins, plus un bonus de mémorisation sur les paires voisines vues à l’entraînement. Le bonus d’une copie paraphrasée ne se transfère qu’à 1 % sur le texte original. Le gain d’exactitude affiché est une valeur inventée pour l’illustration. Comme dans le papier, une copie unique du test passe presque toujours inaperçue ; la détection devient fiable à partir de quelques copies.
