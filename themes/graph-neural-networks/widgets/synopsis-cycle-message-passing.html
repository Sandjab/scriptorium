Vue d'ensemble

Le cycle de message passing déroulé sur un graphe jouet : MESSAGE → AGRÉGATION → MISE À JOUR, puis LECTURE

Six nœuds, six arêtes, des états à deux composantes (teinte = direction du vecteur, rayon = norme). La même boucle MESSAGE → AGRÉGATION → MISE À JOUR se répète pendant T = 3 pas, puis une LECTURE invariante par permutation produit le vecteur du graphe entier. Choisissez le nœud focal (une simple loupe : tous les nœuds calculent en même temps), avancez phase par phase ou déroulez d'un trait ; le halo doré montre le champ récepteur qui s'élargit d'un saut par pas. Tout est calculé exactement, sans aucun aléa : rejouez, vous retrouverez les mêmes nombres.

Mécanismes reliés (actifs à cette phase)

    Pour situer les mécanismes : chaque architecture instancie les trois fonctions de ce cycle. GCN remplace la somme brute par une somme normalisée par les degrés ; GraphSAGE échantillonne N(v) au lieu de le parcourir en entier ; GAT pondère chaque message par un coefficient d'attention appris sur l'arête ; GIN garde la somme, justement parce qu'elle distingue des multi-ensembles que la moyenne ou le max confondent (lien avec le test de Weisfeiler-Lehman). Le halo qui s'élargit d'un saut par pas éclaire aussi les pièges : trop peu de pas et l'information lointaine n'arrive jamais (et se comprime dans les goulots, l'oversquashing) ; trop de pas et les états se confondent (l'oversmoothing).
