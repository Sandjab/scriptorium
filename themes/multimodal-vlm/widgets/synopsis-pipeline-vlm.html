Le pipeline VLM déroulé sur une image jouet : patchs → ViT gelé → connecteur commutable → séquence du LLM → réponse

Une image jouet de 336 × 336 (un chat roux dans l'herbe, un soleil), la question « De quelle couleur est le chat ? », et quatre phases chaînées : patchs + ViT CLIP gelé, connecteur, séquence d'entrée, génération. Le connecteur se commute à tout moment — projection MLP (LLaVA), Q-Former (BLIP-2), Perceiver Resampler (Flamingo) — et la fiche de droite suit ce qui change : nombre de tokens visuels, longueur de séquence, entraîné vs gelé. Mécanismes reliés (actifs à cette phase)

    Les trois voies de fusion se referment ici : même encodeur gelé, même question, trois connecteurs. LLaVA maximise la fidélité — toute la grille passe, séquence longue, LLM affiné par instruction-tuning. BLIP-2 minimise l'entraînement — un goulot appris de 32 tokens entre deux modèles gelés. Flamingo sort la vision de la séquence — 64 latents consultés par cross-attention à porte, langage intact. Deux licences de l'instance jouet : la tokenisation « un mot = un token » est une simplification, et le vrai Flamingo encode l'image avec un NFNet entraîné contrastivement (gelé lui aussi) plutôt qu'avec le ViT de CLIP — la logique du Resampler est inchangée.
