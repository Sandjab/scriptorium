Pipeline LangExtract de bout en bout : découpage → génération contrainte → passes multiples → ancrage source

Un document jouet — une note clinique de 6 médicaments — traverse les cinq phases chaînées de LangExtract. (1) Découpage en blocs ≤ max_char_buffer, aux frontières de phrases/paragraphes. (2) Génération contrainte par bloc — controlled generation Gemini (response_schema) garantissant un JSON syntaxiquement conforme — blocs envoyés en parallèle (max_workers). (3) Passes multiples (extraction_passes) : la stochasticité du LLM fait émerger des entités manquées, puis déduplication « first-pass wins » sur chevauchement d'empans. (4) Resolver d'ancrage : alignement flou difflib → char_interval(start_pos, end_pos) (end_pos exclusif), ou None si la chaîne est introuvable — hallucination filtrée à coût nul, sans appel LLM. (5) Visualisation des empans surlignés (lx.visualize()). Faites varier la taille de bloc et le nombre de passes ; tout est déterministe, calculé exactement.

Pipeline déterministe (aucun Math.random). Les blocs sont calculés exactement à partir de la chaîne source (frontières de phrases, jamais coupées) ; un bloc plus court tient mieux dans l'attention du modèle, d'où un meilleur rappel en une passe — au prix de plus d'appels (appels = blocs × passes). Le rappel affiché est exact sur l'instance jouet (entités ancrées / 6) ; les paliers ≈ 85 → 93 → 96 % (1→3 passes) sont une estimation tierce illustrative, non un benchmark officiel Google. L'ancrage utilise un alignement flou type difflib (ratio de similarité) : EXACT = sous-chaîne littérale, FUZZY = meilleure fenêtre au-dessus du seuil (ici « paracetamol »→« paracétamol »), None = aucune fenêtre suffisante (l'hallucination « morphine » est écartée sans appel LLM). Attention : char_interval = None ne capte qu'un sous-ensemble des hallucinations — une correspondance FUZZY reçoit un intervalle non nul même quand la valeur est sémantiquement fausse.
