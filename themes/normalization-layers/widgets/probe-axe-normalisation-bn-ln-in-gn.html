Axe de normalisation : BN / LN / IN / GN

Un même tenseur (N, C, H·W) : N exemples (cartes), C canaux (lignes), H·W positions spatiales (colonnes). Toutes les méthodes appliquent la même formule — elles ne diffèrent que par le jeu de cellules sur lequel la paire (μ, σ²) est estimée. Survolez une cellule : son groupe de normalisation s'isole, le reste s'estompe.

Le renversement d'axe — et pourquoi BatchNorm s'effondre à N=1

BatchNorm est la seule méthode qui traverse les exemples : sa couleur, fixée par le canal c, est partagée par toutes les cartes (la statistique moyenne sur l'axe batch N). LayerNorm / InstanceNorm / GroupNorm au contraire ne sortent jamais d'un exemple : chaque carte est coloriée indépendamment, et l'on ne fait que découper plus ou moins finement la dimension des features (C·H·W entière → bandes de canaux → un canal). C'est ce renversement d'axe — moyenner à travers le batch versus à l'intérieur d'un exemple — qui structure tout le sujet.

GroupNorm est le continuum. Avec g = ⌊c·G/C⌋ : G = 1 place tous les canaux dans un seul groupe → carte entière → LayerNorm ; G = C donne un canal par groupe → InstanceNorm. Glissez G pour voir les bandes se subdiviser.

Le cas N = 1. Avec un seul exemple, la moyenne « sur l'axe N » n'a aucun autre exemple à moyenner : le groupe BatchNorm d'un canal se réduit aux mêmes cellules que InstanceNorm → BN ≡ IN, les deux coloriages coïncident. Si en plus H·W = 1 (un MLP, pas de spatial), le groupe se réduit à une seule cellule : σ² = 0 exactement, et x̂ = (x−x)/√ε ≈ 0 écrase le signal. C'est l'échec structurel de BatchNorm à petit batch ; LayerNorm/RMSNorm l'évitent par construction (indépendants de N).
