Erase-and-check : la robustesse certifiée par effacement de suffixe

Un suffixe adversarial (façon GCG) camoufle une requête nuisible aux yeux du filtre de sécurité. Erase-and-check (mode suffixe) efface les derniers tokens un par un, de 0 à d, et soumet chaque sous-séquence au filtre : si une seule est signalée, le prompt entier est rejeté. Réglez la longueur du suffixe ℓ et le paramètre d, puis lancez la vérification.

Ce que la sonde démontre : si le filtre reconnaît le prompt nuisible propre, alors toute attaque par suffixe de longueur ℓ ≤ d est nécessairement détectée — à l'étape i = ℓ, l'effacement restitue exactement ce prompt propre. La précision sur prompt attaqué est donc bornée par la précision du filtre sur prompt propre (Kumar et al., COLM 2024 : 92 % de précision certifiée à d = 20 sur les 520 prompts nuisibles d'AdvBench avec un filtre Llama 2 ; 100 % sur 120 prompts de test avec un filtre DistilBERT entraîné). Le prix : d + 1 passes du filtre par prompt, et une perte d'utilité — le scénario « bénin ambigu » montre qu'effacer le contexte peut créer un faux positif. Filtre jouet, pire cas : un seul token adversarial restant suffit à le tromper.
