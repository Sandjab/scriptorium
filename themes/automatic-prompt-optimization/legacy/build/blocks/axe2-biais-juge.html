Biais documentés du juge — décalages systématiques, pas du bruit

Le reward hacking exploite des failles ; mais le juge a aussi des biais de structure, attestés et reproductibles. Ils ne s'effacent pas en moyennant : ce sont des décalages de moyenne (le juge se trompe toujours dans le même sens), distincts du bruit aléatoire σ ≈ 0.08. On ne peut donc pas les noyer dans le seuil de décision ε = 2σ = 0.16 : il faut les corriger en amont, sinon ils se confondent avec un vrai signal entre versions v0..v3. Cinq familles, leur mécanisme, leur symptôme sur le comparatif d'outils Claude Code (requêtes [CLI, MCP, IDE]), et la parade.

Évaluation symétrique A/B + B/A et agrégation des deux ordres (order-swap, déjà au protocole).

Anonymisation des candidats ; held-out set distinct du set d'optimisation ; prompt du juge ≠ fonction de récompense.
Biais ≠ bruit : deux traitements disjoints

Le bruit σ ≈ 0.08 se réduit par répétition (l'erreur-type tombe en σ/√k) ; un biais de structure, lui, ne bouge pas quand on répète — il faut neutraliser sa cause (swap, juge tiers, contrôle de longueur). Sinon un décalage de +10 à +25 % d'auto-favoritisme passe pour un gain réel v(n)→v(n+1) alors qu'il dépasse ε sans aucune amélioration du skill.

Exemplesbiais de position, mesuré — le taux de flip d'ordre

On mesure le biais de position par un order-swap : on juge chaque paire deux fois — (A,B) puis (B,A) — et on compte les paires dont le gagnant change. Sur le comparatif d'outils Claude Code, requêtes [CLI, MCP, IDE], candidats v0..v3.

Le diagnostic : taux de flip
paires jugées (les deux ordres) : 50 paires où le gagnant change au swap : 19 taux de flip = 19 / 50 = 0.38 # 38 % décidés par l'ordre, pas le contenu cohérence au swap = 1 − 0.38 = 0.62 # cf. Zheng 2023 : GPT-4 ~65,0 %

Un flip à 38 % rend toute conclusion en une seule passe non fiable : l'écart mesuré entre deux versions est en partie un artefact de position, pas un vrai gradient de qualité.

La parade : order-swap + agrégation des deux ordres
verdict(v2,v3) sur (A,B) : v3 verdict(v2,v3) sur (B,A) : v2 # renversé → paire contaminée par la position → désaccord : on ne crédite NI v2 NI v3 (ex æquo) verdict(v0,v3) sur (A,B) : v3 verdict(v0,v3) sur (B,A) : v3 # stable aux deux ordres → gain robuste : compté

On ne garde que les verdicts stables aux deux ordres ; les paires qui flippent sont neutralisées avant tout calcul de score. Le 38 % de flip n'entre jamais dans la moyenne du juge.

Pourquoi ça précède le test contre ε
σ ≈ 0.08 → ε = 2σ = 0.16 # seuil de décision (bruit) SANS swap : Δ(v3,v2) mesuré = 0.21 > ε # « gain retenu » — mais 38 % est de l'ordre AVEC swap : Δ(v3,v2) net = 0.05 < ε # dans le bruit → NON significatif

Le biais de position est un décalage systématique : on le neutralise avant de comparer l'écart à ε. Le confondre avec du bruit reviendrait à déclarer un faux gain entre v2 et v3.
